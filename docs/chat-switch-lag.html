Long chats laid out every message on every frame

The sidebar animation, typing, and scrolling all lagged in long chats for the same reason. Each frame rebuilt and laid out the whole thread, not just what was on screen. The sidebar slide asks for a frame every 16 ms and changes the chat column's width each time, so every message was re-wrapped about ten times per toggle.

With 400 messages, a sidebar frame took 180 ms at the median, and 149 ms of that was GPUI layout. A typing frame took 630 ms. After the changes below, the same frames take 3 to 5 ms.

The before numbers for sidebar and switch are flattered by the old placeholder budget, which still had most rows as gray bars at that point. Typing and scrolling ran after every row was revealed, and show the real cost of a fully painted thread.

Fixes, and what each one bought

ChangeSidebar p50 after
Baseline180.2 ms
Virtualized message list, shared cached views, attachment cache, background highlighting9.0 ms
Code blocks as one styled text instead of a div per token4.5 ms
Clipboard poll throttle, window title set only on change3.9 ms
  • Virtualized list. The chat column is now a GPUI list with ListState, bottom-aligned. Only rows in view (plus 800 px of overdraw) are built and measured. Rows off screen keep their cached height. A width change during the slide re-measures only the visible rows, about three per frame instead of 400.
  • No per-frame copies. render_messages used to clone every message and deep-clone every cached markdown view each frame. Rows now read one message by index, and cached views are shared behind Rc.
  • Attachments cached. Each row ran a SQLite query for its attachments on every frame. The result is now cached per message and cleared on a thread switch.
  • Plain first, colors later. A row whose code has not been highlighted yet shows plain code right away, and syntect runs on a background thread for that message only. This replaces the skeleton placeholders from the last pass: nothing waits on a gray bar any more.
  • Code blocks as one text element. Highlighted code created a div per token per line, hundreds of layout nodes per block. Each block is now a single StyledText with a color run per token.
  • Per-frame work in render. With clipboard watch on, every frame read the system clipboard. That now happens at most every 500 ms. The window title was sent to the compositor on every frame, and now only when it changes.

Dev builds

cargo run used to build GPUI, its text shaping, and syntect without optimization. Even with only three rows built per frame, re-wrapping their text took hundreds of milliseconds. [profile.dev.package."*"] now builds dependencies at opt-level = 3, while the workspace crates stay unoptimized for fast rebuilds. The table below is the dev build with two 100-message chats.

The tools

RONIN_FPS=1 still shows the overlay. The frame profiler now also measures GPUI layout and paint, via a zero-size probe element at the end of the tree. Before, it only timed element construction, which is why the earlier pass missed this.

RONIN_PERF_SCENARIO=1 drives the window through ten sidebar toggles, eight chat switches, typing, and scrolling. It then writes p50, p95, and max frame times, the render, layout, and paint split, and rows built per frame to RONIN_PERF_OUT, and quits.

cargo run -p ronin --release --bin switch_profile -- --seed /tmp/ronin-perf --messages 400
XDG_CONFIG_HOME=/tmp/ronin-perf/config XDG_DATA_HOME=/tmp/ronin-perf/data \
  RONIN_PERF_SCENARIO=1 RONIN_PERF_OUT=/tmp/ronin-perf/frames.txt \
  cargo run -p ronin --release

Keep the window visible while it runs. Wayland compositors stop sending frames to hidden windows, and the run then records nothing.

switch_profile without --seed still produces the CPU-side switch breakdown from the last pass. Syntax highlighting is the most expensive single step there, at 179 ms for 49 KB of code, and it is now off the UI thread.
